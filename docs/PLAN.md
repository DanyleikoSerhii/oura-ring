# План реализации: дашборд здоровья Oura Ring

Личный дашборд на Vue 3 для одного пользователя (владельца кольца). Запускается локально. Показывает всю историю данных Oura и даёт то, чего нет в приложении Oura: плотный обзор на одном экране, сравнение периодов и корреляции между метриками.

## 0. Принятые решения

| Вопрос | Решение |
| --- | --- |
| Пользователи | Только владелец, один аккаунт Oura |
| Где работает | Только локально (`pnpm dev` / `pnpm preview`), продакшен-деплоя нет |
| Авторизация | OAuth2 (личные токены Oura отключены в декабре 2025): разовый вход `pnpm oura:auth`, токены в `.oura-tokens.json`, Vite-плагин подставляет и обновляет их. Экрана входа в приложении нет |
| История | Вся, с первого дня ношения кольца, синхронизируется в IndexedDB |
| Дневной пульс | Не синхронизируется целиком, загружается по запросу за просматриваемый день и кэшируется |
| Главный экран | Один плотный дашборд, все разделы равного веса; отдельные страницы для деталей |
| Устройство | Десктоп в первую очередь |
| Своя ценность | Сравнение периодов, корреляции (конструктор X → Y), свой дизайн |
| Тема и язык | Только тёмная тема, только русский язык |

## 1. Стек

Уже есть в каркасе: Vue 3 (`<script setup>`) + TypeScript, Vite, Vue Router, Pinia, oxlint, oxfmt, `vue-tsc`, pnpm.

Добавить:

| Задача | Выбор | Почему |
| --- | --- | --- |
| Локальная база | `dexie` | Удобная обёртка над IndexedDB, индексы по дате, `liveQuery` для реактивного чтения |
| Графики | `echarts` + `vue-echarts` | Линии, столбцы, гипнограмма, точечные графики, тепловые карты; тёмная тема и большие ряды данных |
| Стили | Tailwind CSS v4 (`@tailwindcss/vite`) + CSS-переменные | Быстрая вёрстка, дизайн-токены в одном месте |
| Даты | `date-fns` (локаль `ru`) | Периоды, недели, форматирование |
| Иконки | `lucide-vue-next` | Лёгкие, импорт по одной |

`@tanstack/vue-query` не нужен: источник данных для интерфейса — локальная база, а не API. Статистику (среднее, медиана, корреляция Пирсона) пишем сами в `utils/stats.ts`, это несколько функций.

## 2. Доступ к Oura API

- **Авторизация.** Личные токены Oura отключены (декабрь 2025), поэтому OAuth2 (authorization code). Разовый вход: `pnpm oura:auth` поднимает `http://localhost:9876/callback`, обменивает код на токены и сохраняет их в `.oura-tokens.json` (в `.gitignore`). `OURA_CLIENT_ID` и `OURA_CLIENT_SECRET` лежат в `.env.local` без префикса `VITE_`. Refresh token одноразовый, поэтому обновление сериализуется и записывается атомарно.
- **Прокси.** Vite-плагин `tools/oura-proxy.ts` (dev и preview) отдаёт `/oura/*` → `https://api.ouraring.com/v2/usercollection/*`, добавляет Bearer-токен на стороне Node, сам обновляет его и повторяет запрос после 401. Это решает CORS, токен не попадает в браузер. Статус входа отдаётся на `/oura-status`.
- **Скоупы.** Реальные имена скоупов расходятся с опубликованной OpenAPI-схемой (`spo2` против `spo2Daily`, `heart_health`, `stress`), а неизвестный скоуп молча отбрасывается. Поэтому по умолчанию запрашиваются оба написания; список можно задать через `OURA_SCOPES`.
- **Пагинация.** В ответах есть `next_token`, клиент забирает все страницы. `end_date` — исключительная граница, а `/sleep` фильтруется по UTC-времени начала сна (не по `day`), поэтому окна расширяются на день в обе стороны.
- **Лимиты.** Oura ограничивает частоту запросов: 5000 за 5 минут на токен, при превышении ответ 429 с заголовком `retry-after`. Первая синхронизация всей истории идёт порциями, например по 90 дней на эндпоинт, последовательно. При ответе 429 ждём и повторяем.
- **Ошибка 401.** Показываем баннер «токен недействителен, обновите `.env.local`».

## 3. Синхронизация и хранение

- **Таблицы Dexie** (ключ — `day` или `id`, индекс по дате): `dailyReadiness`, `dailySleep`, `sleep`, `dailyActivity`, `dailyStress`, `dailyResilience`, `dailySpo2`, `cardiovascularAge`, `vo2Max`, `workout`, `heartrate` (только загруженные по запросу дни), `meta` (дата последней синхронизации по каждому эндпоинту, дата начала истории).
- **Первая синхронизация:** начало истории берём из самого раннего дня, который вернёт API, или из `ring_configuration`; идём порциями от начала до сегодня. Прогресс виден в интерфейсе.
- **Досинхронизация:** при открытии и по кнопке «Обновить» тянем данные с даты последней синхронизации минус 2 дня. Oura пересчитывает последние дни задним числом, поэтому их перезаписываем.
- **Дневной пульс:** при открытии дня загружаем `heartrate` за эти сутки и сохраняем. Сегодняшний день перезагружаем при каждом обновлении.
- **Потеря данных** (очистка данных сайта, другой браузер) не страшна: база восстанавливается полной синхронизацией. Есть кнопка «Сбросить и синхронизировать заново».
- **Интерфейс** читает только из Dexie через composable на `liveQuery`, поэтому после синхронизации всё обновляется само.

## 4. Какие данные выводим

Все эндпоинты из `/v2/usercollection/` принимают `start_date` и `end_date` (у `heartrate` — `start_datetime` и `end_datetime`).

| Раздел | Эндпоинт | Ключевые поля |
| --- | --- | --- |
| Готовность | `daily_readiness` | `score`, отклонение температуры, вклады (HRV balance, resting HR, recovery index, предыдущий сон и активность) |
| Сон: сводка | `daily_sleep` | `score`, вклады (глубокий, REM, эффективность, латентность, тайминг, общая длительность) |
| Сон: детали | `sleep` | время отбоя и подъёма, длительности фаз, средние HR и HRV, минимальный HR, `sleep_phase_5_min` (гипнограмма), `heart_rate` и `hrv` за ночь |
| Активность | `daily_activity` | `score`, шаги, калории, минуты высокой, средней и низкой активности, неактивное время |
| Пульс | `heartrate` | ряд `bpm` с источником (покой, активность, сон), по запросу |
| Стресс | `daily_stress` | `stress_high`, `recovery_high`, `day_summary` |
| Устойчивость | `daily_resilience` | `level`, вклады |
| SpO2 | `daily_spo2` | средний SpO2, индекс нарушений дыхания |
| Сердечно-сосудистая система | `daily_cardiovascular_age`, `vO2_max` | сосудистый возраст, VO2 max |
| Тренировки | `workout` | тип, длительность, калории, интенсивность |

## 5. Экраны

1. **Дашборд** (`/`). Плотная сетка на один экран 1440×900 без скролла, насколько возможно:
   - верхняя строка: выбранный день, три кольца скоров (готовность, сон, активность) и плитки (пульс в покое, HRV, температура, шаги, SpO2, стресс), у каждой плитки отклонение от личной базовой линии (медиана за 30 дней);
   - карточки равного веса: сон прошлой ночи (гипнограмма и фазы), пульс за сутки, активность дня, вклады в готовность;
   - нижняя строка: спарклайны ключевых метрик за 30 дней.
2. **Сон** (`/sleep`): детали ночи, тренд скора и длительности, регулярность отбоя и подъёма.
3. **Активность** (`/activity`): шаги и калории по дням, интенсивность, тренировки.
4. **Восстановление** (`/recovery`): готовность и вклады, HRV, пульс в покое, температура, стресс, устойчивость, SpO2, VO2 max, сосудистый возраст.
5. **Сравнение периодов** (`/compare`): два периода (эта неделя и прошлая, месяц к месяцу, произвольные диапазоны). Таблица метрик: значение A, значение B, разница в абсолютных числах и процентах. Графики двух периодов наложены друг на друга.
6. **Корреляции** (`/correlations`): конструктор X → Y.
   - Выбор метрики X, метрики Y и сдвига: тот же день или Y на следующий день (например, «время отбоя → HRV следующей ночи»).
   - Точечный график с линией тренда, коэффициент Пирсона `r`, число дней `n`, p-value.
   - Если `n < 30` или `|r| < 0.2`, связь помечается как слабая или недостаточно данных. Под графиком напоминание, что корреляция не означает причинность.
   - Период анализа по умолчанию — вся история.
7. **Синхронизация** (`/sync`, или панель в шапке): статус по эндпоинтам, прогресс первой загрузки, кнопки «Обновить» и «Сбросить».

Выбранный день и период хранятся в Pinia и отражаются в query-параметрах URL.

## 6. Дизайн

- **Направление:** только тёмная тема, спокойный фон, мягкие карточки, акцент на числах. Десктоп в первую очередь; на узком окне сетка просто перестраивается в меньшее число колонок, отдельной мобильной вёрстки нет.
- **Токены** (CSS-переменные в `:root`, подключаются в Tailwind через `@theme`):
  - фон `#0B0D12`, поверхность `#151922`, граница `#232836`, текст `#E8EAF0` и `#8A90A2`;
  - акценты по разделам: сон — индиго `#7C83FD`, готовность — бирюза `#3DD6C6`, активность — оранжевый `#FF9F5A`, пульс — коралл `#FF6B81`;
  - статус скора: 85+ оптимально `#3DD68C`, 70–84 хорошо `#F5C451`, ниже 70 внимание `#FF6B6B`.
- **Типографика:** Inter; числа скоров крупные (40–56 px), цифры одинаковой ширины (`tabular-nums`).
- **Сетка:** 12 колонок, контейнер до 1600 px; навигация — узкая боковая панель с иконками.
- **Компоненты:** `ScoreRing`, `MetricTile` (значение, единица, отклонение от базовой линии, спарклайн), `ChartCard` (обёртка для ECharts с состояниями загрузки, пустых данных и ошибки), `Hypnogram`, `ContributorBar`, `DateRangePicker`, `MetricSelect`, `ScatterWithTrend`, `SyncStatus`.
- **Состояния:** скелетоны при первой синхронизации, понятная заглушка для дней без данных (кольцо не носили).
- **Доступность:** контраст по WCAG AA, цвет не единственный носитель смысла (подписи диапазонов), учитываем `prefers-reduced-motion`.
- Общая тема ECharts строится из тех же токенов.

## 7. Структура кода

```
src/
  api/
    client.ts          # fetch к /oura, пагинация next_token, повтор при 429, ошибка 401
    endpoints.ts       # функции по эндпоинтам
    types.ts           # типы ответов Oura API
  db/
    schema.ts          # Dexie: таблицы и индексы
    sync.ts            # первая синхронизация, досинхронизация, пульс по запросу
  metrics/
    registry.ts        # реестр метрик: id, название, единица, как достать значение по дню
  stores/
    period.ts          # выбранный день и периоды
    sync.ts            # статус и прогресс синхронизации
  composables/         # useLiveQuery, useDayData, useSeries, useBaseline
  components/
    ui/                # ScoreRing, MetricTile, ChartCard, ContributorBar, ...
    charts/            # Hypnogram, HeartRateChart, TrendChart, ScatterWithTrend, тема ECharts
    layout/            # AppShell, боковая навигация
  views/               # DashboardView, SleepView, ActivityView, RecoveryView, CompareView, CorrelationsView, SyncView
  utils/               # stats.ts (mean, median, pearson, p-value), форматирование длительностей, диапазоны скоров
```

`metrics/registry.ts` — общий список метрик для плиток, сравнения периодов и конструктора корреляций: каждая метрика описана один раз.

Демо-файлы шаблона (`HelloWorld`, `TheWelcome`, `WelcomeItem`, `icons/`, стор `counter`, `AboutView`, стили шаблона) удаляются на первом этапе.

## 8. Этапы

1. **Основа:** удалить заглушки; подключить Tailwind, токены темы, шрифт; `AppShell` с боковой навигацией и роутами-заглушками.
2. **Доступ к API:** проверить, как сейчас получить токен; `.env.example`, Vite-прокси с заголовком, `api/client.ts` и типы.
3. **Синхронизация:** схема Dexie, первая синхронизация всей истории и досинхронизация, статус синхронизации в интерфейсе, `liveQuery`-composable.
4. **Реестр метрик и дашборд:** `metrics/registry.ts`, базовые линии, кольца, плитки, карточки сна, пульса и активности.
5. **Детальные страницы:** сон, активность, восстановление.
6. **Сравнение периодов.**
7. **Корреляции:** `utils/stats.ts`, конструктор X → Y.
8. **Полировка:** пустые состояния и ошибки, производительность графиков на всей истории.
